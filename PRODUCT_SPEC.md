# PRODUCT_SPEC.md

## Product Name

RITWIK OS

## Tagline

**Engineering Intelligence into Production.**

## Product Summary

RITWIK OS is a production-grade engineering portfolio and personal engineering platform. It is a static-first web experience built to showcase engineering work, explain architectural thinking, publish technical writing, document ongoing builds, and create a memorable recruiter experience.

The platform should communicate professional credibility through clarity, depth, taste, and technical execution.

## What This Product Is

RITWIK OS is:

- A personal engineering brand platform
- A portfolio of flagship software projects
- A technical writing archive
- A build log for ongoing engineering work
- A place to demonstrate architecture judgment
- A recruiter-friendly professional surface
- A production-quality frontend system

## What This Product Is Not

RITWIK OS is not:

- A SaaS application
- A dashboard product
- A CRUD tool
- A multi-user system
- A productivity suite
- A fake browser-based operating system
- A database-backed app
- An authenticated platform

## Product Goals

1. Help recruiters quickly understand Ritwik's engineering profile.
2. Help technical reviewers inspect real engineering depth.
3. Present flagship projects as case studies, not just cards.
4. Publish architecture and implementation writing.
5. Maintain a public record of ongoing engineering builds.
6. Create a distinctive experience without sacrificing usability.
7. Demonstrate production-grade frontend architecture.

## Audience

### Recruiters

Recruiters need fast access to:

- Role positioning
- Resume
- Flagship projects
- Contact links
- Professional summary

### Engineering Managers

Engineering managers need evidence of:

- Judgment
- Ownership
- Technical communication
- Product sense
- Delivery quality

### Engineers

Engineers need access to:

- Architecture details
- Code links
- Tradeoff analysis
- Implementation notes
- Testing and performance decisions

## Core User Journeys

### Recruiter Journey

1. Land on home page.
2. Understand positioning within seconds.
3. Review flagship work.
4. Open resume.
5. Contact or visit LinkedIn/GitHub.

### Engineering Reviewer Journey

1. Land on home or work page.
2. Open a flagship project.
3. Read problem, architecture, tradeoffs, and implementation details.
4. Inspect code/demo links.
5. Read related architecture notes or articles.

### Returning Reader Journey

1. Visit writing or builds.
2. Browse recent technical posts.
3. Open a build log or article.
4. Follow related work.

## Homepage Requirements

The home page should:

- Clearly identify RITWIK OS.
- Display the tagline.
- State Ritwik's engineering positioning.
- Surface flagship work.
- Surface recent writing or builds.
- Provide a clear recruiter path.
- Provide links to GitHub, LinkedIn, resume, and contact.
- Avoid generic hero copy.

## Work Section Requirements

The work section should present selected engineering projects with enough context to evaluate technical quality.

Each project should include:

- Title
- Short summary
- Year
- Role
- Stack
- Domain
- Status
- Links where applicable
- Case study

## Case Study Requirements

Each flagship project case study should include:

- Executive summary
- Problem statement
- Context and constraints
- Architecture overview
- Key technical decisions
- Tradeoffs
- Implementation details
- Testing approach
- Performance considerations
- Accessibility considerations when relevant
- Screenshots or diagrams when available
- Links to source/demo when available
- Outcome and lessons learned

## Writing Requirements

Writing should focus on engineering substance. Acceptable categories include:

- Architecture essays
- Implementation notes
- Frontend engineering
- Performance analysis
- Testing strategy
- Design system thinking
- Postmortems
- Build-vs-buy analysis

## Builds Requirements

Build logs should document active or recent engineering work. They should be concrete and technical, not diary-style filler.

Each build entry should include:

- What is being built
- Current state
- Technical challenge
- Decisions made
- Next step

## Resume Requirements

The resume route should be highly scannable and recruiter-friendly.

It should include:

- Professional summary
- Core skills
- Selected experience
- Flagship projects
- Education or credentials where relevant
- Contact links
- Optional PDF link when available

## Success Criteria

RITWIK OS succeeds if:

- A recruiter can understand the professional value in under 60 seconds.
- An engineer can find deep technical evidence within two clicks.
- Project pages read like credible engineering case studies.
- The site loads quickly and feels polished.
- The site is accessible by keyboard and screen readers.
- The implementation itself demonstrates strong engineering standards.
